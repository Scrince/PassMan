PassMan Windows Release Verification
====================================

Current release status
----------------------

PassMan v1.1.0 for Windows x64 was built locally from the working tree on
2026-11-04 with Windows 11, Python 3.14.5, PyInstaller 6.22.3, and Inno
Setup 6.7.3. It adds Change Vault in Settings. PassMan locks the current
vault before opening another and remembers the selected file after unlock.
Closing Settings without changing a control skips the encrypted vault save,
which avoids the Argon2id delay on an unchanged close.

Artifacts under release/v1.1.0/windows/

  PassMan.exe
  PassMan-Setup-1.1.0.exe
  SBOM.cdx.json
  SHA256SUMS

All four files have detached OpenPGP signatures. The executable and installer
also carry DigiCert-timestamped Authenticode signatures from the local
self-signed certificate described below. Windows reports an untrusted root
for that certificate. The OpenPGP signatures were verified with the release
public key in a separate keyring. Ruff and all 31 unit tests passed.
The packaged executable passed a 10-second offscreen startup check. The
switch flow was tested from source with synthetic vaults.

Verify the current build from the repository root:

  gpg --import docs/PassMan_Release_Signing_2026_pubkey.asc
  gpg --verify release/v1.1.0/windows/SHA256SUMS.asc release/v1.1.0/windows/SHA256SUMS
  gpg --verify docs/SHA256SUMS.asc docs/SHA256SUMS
  Get-Content release/v1.1.0/windows/SHA256SUMS
  Get-FileHash -Algorithm SHA256 release/v1.1.0/windows/PassMan.exe,release/v1.1.0/windows/PassMan-Setup-1.1.0.exe,release/v1.1.0/windows/SBOM.cdx.json

To verify an individual file, run gpg --verify with its .asc signature
followed by the file path.

Published v1.0.8 release
------------------------

The v1.0.8 Windows x64 executable, installer, and CycloneDX SBOM were built on
Windows 11 x64 with Python 3.14.5, PyInstaller 6.22.3, and Inno Setup 6.7.3.
Build date: 2026-11-03. Packages were built locally and verified before
publication at https://github.com/Scrince/PassMan/releases/tag/v1.0.8.
The release also includes the existing macOS and Ubuntu 24.04 Linux v1.0.8
packages. Package checksums identify the exact distributed bytes; packages
were not rebuilt from the final documentation and publication commit.

This version adds Apple Passwords CSV import and reconciliation, including
OTPAuth authenticator imports, with validation and password-whitespace fixes.

Artifacts:

  release/v1.0.8/windows/PassMan.exe
  release/v1.0.8/windows/PassMan-Setup-1.0.8.exe
  release/v1.0.8/windows/SBOM.cdx.json
  release/v1.0.8/windows/SHA256SUMS

All artifacts and the Windows checksum manifest have detached OpenPGP
signatures. The three artifact hashes are included in the signed aggregate
manifest at docs/SHA256SUMS.

The executable and installer also carry SHA-256 Authenticode signatures with
DigiCert timestamps, using the local self-signed certificate:

  Subject: CN=PassMan Local Code Signing
  Thumbprint: 554A90C89385DD8C72D2341FF28BE155F3FC511A
  Valid: 2026-07-04 to 2028-07-04

This certificate is not a publicly trusted publisher identity. On this build
host, Get-AuthenticodeSignature reports UnknownError with an untrusted-root
message. Both signatures contain the expected signer and timestamp certificate.
Do not treat that status as public Windows trust or SmartScreen reputation.
Use the verified OpenPGP signatures and checksums to authenticate these files.

Build environment (run on Windows 11 with Inno Setup 6 or newer):

  uv sync --locked --extra build --extra dev
  .venv\Scripts\python.exe -m ruff check src tests scripts build.py
  .venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
  .venv\Scripts\python.exe build.py --platform windows --skip-package

The executable was Authenticode-signed before compiling the installer so the
installed PassMan.exe retains its signature. The installer was then signed,
and the final signed bytes were copied to release/v1.0.8/windows. Follow the
Windows Authenticode steps in docs/Build.txt for that sequence. The ordinary
build.py command builds both packages without Authenticode signing.

Generate the SBOM from the same Python environment used for the build:

  .venv\Scripts\python.exe scripts/generate_release_sbom.py --target "Windows 11" --architecture "x64" --build-environment "Windows 11, Python 3.14.5, PyInstaller 6.22.3, Inno Setup 6.7.3; uv.lock with build and dev extras" --output release/v1.0.8/windows/SBOM.cdx.json

The release was signed with the repo-local release key. `docs/Build.txt`
contains the full signing procedure and verification commands.

Verification completed:

  - Ruff passed and all 28 unit tests passed with the locked dependencies.
  - The packaged executable stayed running for a 10-second offscreen Qt
    startup check. No vault was created or unlocked. This is a startup smoke
    check, not a full interactive installer or end-to-end UI test.
  - The release and dist executable/installer copies have identical bytes.
  - All v1.0.8 platform manifests, artifact signatures, and the aggregate
    manifest were checked using a temporary keyring with only the public key.
